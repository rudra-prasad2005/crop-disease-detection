# Plant Disease Detection

Deep-learning classifier for plant-leaf diseases using the **PlantVillage**
dataset (38 classes across 14 crop species, ~54k images) and **EfficientNetB0**
transfer learning.

## Dataset

The dataset ships in `archive.zip` (~2 GB) as `plantvillage dataset/{color,
grayscale,segmented}/<Class>/<image>.JPG`. Only the `color/` variant is used.

There is **no pre-existing train/valid split**, so `src/data.py` auto-splits
each class folder into **80% train / 20% valid** with a fixed seed
(`config.SEED = 42`). Per-class stratified split ensures every class appears in
both sets despite minor class imbalance.

## Installation

```bash
# Tested with Python 3.10/3.11, TensorFlow 2.15+, single CUDA GPU.
pip install -r requirements.txt
```

For TensorFlow with GPU support, follow the official install matrix
(<https://www.tensorflow.org/install/pip>) — the `requirements.txt` only pins
CPU-compatible versions.

## How to run

From the **project root** (`crop disease/`):

```bash
# 1. Extract the archive, build the train/valid split, train both phases,
#    save outputs/best_model.h5 and outputs/training_curves.png.
python -m src.train

# 2. Evaluate on the validation set: classification report + confusion matrix.
python -m src.evaluate

# 3. Generate Grad-CAM visualizations in outputs/gradcam/.
python -m src.explain

# 4. Predict on a single image.
python -m src.predict path/to/leaf.jpg --top-k 3
```

The first run takes the longest (extract → split → train). Subsequent runs
skip extraction and splitting if `data/raw/plantvillage dataset/color/` and
`data/splits/` already exist.

## Model & training details

- **Base**: EfficientNetB0 pretrained on ImageNet (`include_top=False`),
  default in `src/config.py::BASE_MODEL_NAME`. Swap to `"MobileNetV2"` by
  editing that one line.
- **Head**: `GlobalAveragePooling2D → Dropout(0.3) → Dense(38, softmax)`.
  Input preprocessing matches the selected backbone: EfficientNet receives
  pixels in `[0, 255]` and uses its built-in rescaling; MobileNetV2 receives
  pixels normalized to `[-1, 1]`. Inference accepts ordinary RGB images.
- **Augmentation** (training only): random rotation, horizontal+vertical
  flip, zoom, brightness shift. Conservative magnitudes — leaves in the field
  appear in any orientation. Fresh augmentations are generated each epoch.
- **Two-phase training**:
  - Phase 1: base frozen, head trained at `lr=1e-3` for up to 10 epochs.
  - Phase 2: top 50 base layers fine-tuned (batch-normalization layers stay
    frozen) at `lr=1e-5` for up to 10 more epochs.
  - The saved model is whichever phase achieved the higher validation accuracy.
- **Callbacks**: `EarlyStopping(patience=5, restore_best_weights=True)`,
  `ModelCheckpoint(save_best_only=True)`, `ReduceLROnPlateau(factor=0.5,
  patience=3)`.
- **Optimizer / loss**: Adam, categorical cross-entropy.

## Hardware

- Designed for a **single-GPU** environment (Colab / Kaggle / local CUDA).
- CPU-only training is technically possible but ~10-50x slower.
- 224x224 input + 32 batch size fits comfortably in ~4 GB of VRAM.

## Updating an existing model

After changing preprocessing or the training pipeline, retrain the model so
`outputs/best_model.h5` matches the current code:

```bash
python -m src.train
python -m src.evaluate
```

The held-out validation set comes from PlantVillage. Good validation results
do not guarantee equal performance on phone photos or other field conditions;
include representative labeled images from the intended use case when
evaluating real-world performance.

## Reproducibility

`set_seed(42)` is called at the top of every entry-point script. TF's
`enable_op_determinism` is enabled when available. Note: full GPU determinism
is not guaranteed (CUDA has non-deterministic kernels), so absolute
bit-identical reproduction across machines isn't possible — but re-runs on
the same machine will be very close.

## Notes / non-obvious choices

1. **Two `image_dataset_from_directory` calls**, not `validation_split=`.
   The latter is fragile: the split is regenerated from a hash of file paths
   and silently re-shuffles whenever files are added to the source.
2. **Per-class split** in `data.make_splits` — `image_dataset_from_directory`
   doesn't expose stratified splits, so we build the directories ourselves.
3. **Rescaling inside the model** — keeps preprocessing in one place.
4. **EfficientNetB0 over MobileNetV2** — better accuracy at the same input
   size; both are supported via `config.BASE_MODEL_NAME`.
5. **Grad-CAM on `top_conv`** for EfficientNetB0 (or `Conv_1` for
   MobileNetV2) — see `model.last_conv_layer_name`.
